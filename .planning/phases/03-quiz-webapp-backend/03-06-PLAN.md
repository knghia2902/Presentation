<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → reconnect | Browser storage may contain stale or user-edited metadata. |
| WebSocket event → UI result | Server events cross into visual/score display. |
| disconnected client → answer handling | A retry can race with deadline/duplicate guards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-22 | Tampering | offline session data | high | mitigate | Persist opaque capability metadata only; server revalidates the token and snapshot on resume. |
| T-03-23 | Tampering/repudiation | answer retry path | high | mitigate | Never queue a disconnected answer; rely on DO accepted-answer identity and authoritative acknowledgement. |
| T-03-24 | Spoofing | connection status | medium | mitigate | Label online only after WebSocket open/resume acknowledgement, not navigator.onLine alone. |
| T-03-25 | Availability | reconnect retry loop | medium | mitigate | Use capped exponential backoff and a visible retry/return path. |
</threat_model>
