# Phase 3 — UI Design Contract

> Visual and interaction contract for the realtime Vietnamese quiz room. Generated by gsd-ui-researcher; checker upgrades `draft` to `approved` after validation.

## Design intent

Build a host-led realtime room quiz that feels energetic during play but remains calm and legible on a phone. The quiz is a projection of server-authoritative room state: the client never advances a question, awards points, or treats a local timer as authoritative.

Use Vietnamese throughout the interface. Do not use the product name “Kahoot”. Use the neutral terms `Phòng chơi`, `Mã phòng`, `Chủ phòng`, `Người chơi`, `Câu hỏi`, `Bảng xếp hạng`.

The visual continuity source is `presentation/slides/style.css`: Be Vietnam Pro, deep ink/navy neutrals, presentation blue, academic gold, crimson for failure. The quiz may feel more vivid than the presentation, but it must not become neon, gradient-heavy, or dependent on emoji.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain HTML/CSS/JS; do not initialize shadcn |
| Preset | not applicable |
| Component library | none; use semantic HTML and small reusable CSS classes |
| Icon library | existing inline SVG pattern from `presentation/slides/index.html`; use 1.75px stroke for outline icons and provide a text label for every icon-only control |
| Font | Be Vietnam Pro, with `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` fallback; do not use Playfair Display for functional quiz text |
| Source continuity | Existing `style.css` tokens: Be Vietnam Pro, `#1971c2` blue, `#d4af37` gold, `#c92a2a` crimson; adapted for a phone-first dark quiz surface |

## Spacing Scale

Declared values are multiples of 4 and are the only spacing tokens used in the quiz UI.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, status dot gaps, compact badge padding |
| sm | 8px | Related control spacing, option label inset, helper text spacing |
| md | 16px | Default page inset on phones, control gaps, field padding |
| lg | 24px | Question card padding, section padding, host panel gaps |
| xl | 32px | Main layout gaps, lobby/result section separation |
| 2xl | 48px | Major screen breaks, desktop result sections |
| 3xl | 64px | Desktop page-level breathing room and final result emphasis |

Exceptions:

- Every tappable control is at least 44px by 44px, even when its visual icon is 20px.
- Player answer buttons are at least 64px tall on phones and 72px tall on desktop to support fast, error-resistant tapping.
- Phone page gutters are 16px; tablet gutters are 24px; desktop content is capped at 1120px with 32px gutters.
- Never use arbitrary 1px/2px spacing except for borders, dividers, and focus rings.

## Typography

Exactly four text sizes and two weights are used. Use tabular numerals for timer, score, room code, and ranking numbers.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.25 |
| Heading | 24px | 600 | 1.2 |
| Display | 40px | 600 | 1.1 |

Application rules:

- Question text uses Heading size on phones and may use Display size only for short questions on wide screens; never let a question exceed 3 lines at 320px width without reducing to 24px.
- Timer and room code use Display size with `font-variant-numeric: tabular-nums; letter-spacing: 0.04em`.
- Body and explanation text remain 16px to protect Vietnamese diacritics and scanning speed.
- Do not use all-caps for Vietnamese sentences. Use sentence case; small status badges may use uppercase only when the surrounding label is still readable.
- `font-weight: 400` is for body, options, explanations, and muted status. `font-weight: 600` is for headings, labels, CTAs, scores, room code, and selected/active states.

## Color

The surface split is approximate by visible area: 60% dominant background, 30% secondary containers, 10% accent/action emphasis.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111827` | Page background, question-stage backdrop, full-bleed result background |
| Secondary (30%) | `#1F2937` | Question panel, lobby panel, leaderboard rows, host control rail, input surfaces |
| Accent (10%) | `#D4AF37` | Room code, primary `Tạo phòng`/`Bắt đầu ván chơi`/`Vào phòng` actions, active progress marker, winner highlight, final top-3 emphasis |
| Text primary | `#F8FAFC` | Headings, questions, selected option text, primary scores |
| Text secondary | `#CBD5E1` | Labels, explanations, inactive metadata |
| Text muted | `#94A3B8` | Helper text, timestamps, offline detail; never use for essential instructions |
| Success | `#22C55E` | Correct result, accepted answer, online status; pair with text/icon, never color alone |
| Destructive/error | `#EF4444` | Incorrect result, timeout urgency, connection failure, destructive actions |
| Focus/info | `#74C0FC` | Keyboard focus ring and non-destructive informational notice only |

Accent reserved for: room code, primary calls to action, current question progress, active host mode, correct winner/trophy emphasis, and the final top three. Do not use gold on every button, every border, or decorative text.

Color behavior:

- Answer options are neutral secondary surfaces before selection. Correct/incorrect feedback uses success/error semantic colors only after the server reveal or answer result is authoritative.
- The timer stays neutral while above 10 seconds, shifts to gold at 10 seconds, and shifts to error red below 5 seconds. The numeric countdown and a progress bar/ring both update so color is never the only urgency signal.
- Use borders and icons to reinforce state. Do not rely on green/red alone for correctness.
- Avoid pure black, white-on-white surfaces, neon gradients, outer glow effects, and translucent text below readable contrast.

## Information architecture and screen contract

The client renders the room state machine `lobby → question → reveal → finished`; `paused_host_disconnect` is an overlay/state that freezes the current view. Every screen has one dominant action and one clear status line.

| Screen/state | Required content | Primary interaction | Required visual states |
|--------------|------------------|---------------------|------------------------|
| Entry / role choice | Short title, `Tạo phòng`, `Tham gia phòng`, audio toggle | Choose host or player path | Default, keyboard focus, loading |
| Create room | Room name/optional session label if implemented, create action | `Tạo phòng` | Invalid input, request loading, server error |
| Join room | `Mã phòng` field, `Biệt danh` field, join action, no-account note | `Vào phòng` | Empty, invalid code, nickname validation, join loading |
| Host lobby | Large room code, share instruction, participant count/list, music toggle, auto/manual advance toggle, start action | `Bắt đầu ván chơi` | Empty participant list, participant joins/leaves, host reconnect, connection status |
| Player lobby | Room code, current nickname, host name/status, participant count, waiting copy | No player-controlled advance | Waiting, host disconnected/paused, player reconnecting |
| Host question | Question number/20, question, four answer rows for preview, 30-second timer, auto/manual mode, participant response count, next/end actions | `Câu tiếp theo` in manual mode | Live timer, waiting for responses, submitted/locked, timeout, host pause |
| Player question | Question number/20, question, four full-width answer buttons, shared timer, answer status | Select exactly one answer | Default, pressed, submitted/locked, server result, timeout, reconnect |
| Reveal | Correct answer, short explanation, player’s awarded score, fastest-correct announcement, current-room leaderboard, host next control | Host: `Câu tiếp theo`; player: wait | Correct, incorrect, unanswered, no correct respondent, auto-advance countdown |
| Paused host | Current question/reveal remains visible but dimmed, clear pause banner, reconnect detail | No player action; host resumes | Host disconnected, reconnecting, resumed |
| Final result | Final score/rank, current-room top 5/20, top-three emphasis, new-room path, global top-20 section when available | `Tạo phòng mới` or `Xem bảng chung` | Result loading, save success, save fallback, no global data |
| Offline/reconnect | Persistent compact status banner plus current screen | Automatic retry; optional `Thử lại` | Reconnecting, reconnected, failed after retry |

Host and player must share the same question/reveal visual language. Host controls are added in a secondary rail/panel; they must not visually compete with the player’s question and timer.

## Component and state inventory

Use semantic, reusable classes/components even in plain HTML/CSS/JS. Each component must have the states listed here; do not implement only the happy path.

| Component | States and behavior |
|-----------|---------------------|
| `QuizShell` | `loading`, `connected`, `reconnecting`, `offline`, `finished`; owns page background, top status bar, safe-area padding, and audio control |
| `RoomHeader` | Shows role (`Chủ phòng`/`Người chơi`), room code, question progress, connection status, and mute control; room code remains readable on phone |
| `RoomCode` | Large selectable code, copy/share affordance for host, copied feedback `Đã sao chép mã phòng`; never hide the code behind an icon-only menu |
| `NicknameField` | Label above input, character limit, helper text, inline validation, duplicate-name suffix explanation; preserve entered text after network failure |
| `QuestionCard` | Question heading, question index, optional category, explanation slot; fixed minimum height during question/reveal transitions to prevent layout jump |
| `AnswerOption` | A/B/C/D marker plus answer text; `default`, `hover`, `focus-visible`, `pressed`, `selected`, `locked`, `correct`, `incorrect`, `unanswered`; after selection disable all options for the current question |
| `Timer` | Numeric seconds plus linear/radial progress; `normal`, `warning` at 10s, `critical` at 5s, `expired`, `paused`; uses server deadline for display offset and never awards points locally |
| `ProgressMarker` | `Câu X/20`; current marker uses gold; completed questions use neutral check/number; do not expose future answer correctness before reveal |
| `HostControlRail` | Auto/manual switch, participant response count, `Câu tiếp theo`, `Kết thúc ván chơi`; disabled when not host or during a pending transition |
| `Leaderboard` | Current room first; rows include rank, nickname, score, and tie-break indicator only when needed; top 3 use gold hierarchy, remaining rows stay neutral; animate reordering with transform/opacity only |
| `StatusBanner` | `Đang kết nối`, `Đã kết nối`, `Mất kết nối`, `Phòng đang tạm dừng`, `Đã ghi nhận câu trả lời`; has `role=status`/`aria-live=polite` and is not color-only |
| `AnnouncementRegion` | Visible text for fixed/dynamic voice messages; `aria-live=polite`; examples: fastest correct, no correct respondent, final top five |
| `AudioControl` | Explicit user-toggle for music/audio; icon plus text label on phones; `muted`, `music-on`, `voice-ducking`, `unsupported` |
| `SaveState` | `Đang lưu kết quả`, `Đã lưu bảng xếp hạng chung`, `Chưa lưu được — kết quả phòng vẫn còn`; never block the final room result on global persistence |
| `ConfirmDialog` | Used for `Kết thúc ván chơi` and host `Rời phòng` if a live room exists; focus-trapped, Escape-cancellable, destructive button visually distinct |
| `SkeletonQuestion` | Loading shape matches real question heading, timer, and four options; use shimmer only when motion is allowed |

Interaction invariants:

- Players can submit one answer only. Once the server acknowledges an answer, all four options are disabled for that question and the selected option remains visibly marked.
- The client never offers a “previous question” or edit path.
- A missed answer is visibly represented as `Không trả lời`/`0 điểm`; it is not queued for later submission after reconnect.
- A host may switch auto/manual mode before the next transition. Only the host can start, advance manually, resume after host disconnect, or finish.
- Player disconnect marks the player offline but does not pause the room. Host disconnect pauses the room and freezes the timer.
- Nickname duplicates are resolved by the server and reflected as `Minh #2`; show a one-time notice rather than treating this as an error.

## Responsive behavior

Mobile is the primary layout. Use `min-height: 100dvh`, not `100vh`, and include `env(safe-area-inset-*)` on the page shell and bottom actions.

| Viewport | Contract |
|----------|----------|
| 320–767px | Single column; 16px side padding; question above answers; answer buttons full width and at least 64px tall; 2×2 answer grid is not allowed; host controls move below the question or into a compact bottom sheet; leaderboard rows are full width; no horizontal scrolling |
| 768–1023px | Single player column capped at 720px; host uses question/content plus a 280px control rail; answer options may use a 2×2 grid only at widths where each option remains at least 44px high and text has room for 2 lines |
| 1024px and wider | Center the player stage at max 760px; host uses a two-column layout with a 1fr question stage and 300px secondary rail; final leaderboard may use a wider 2-column result layout; preserve 32px page gutters |

Responsive interaction rules:

- Keep the timer and connection status in the top visual band on every viewport. Do not make users scroll to discover that the room is paused or disconnected.
- On phones, place the primary action in thumb reach and keep a 16px bottom safe-area buffer. Do not use hover-only affordances.
- Use CSS Grid for answer layouts; never use percentage flex math that can produce narrow tap targets.
- Preserve question card height between `question` and `reveal` to prevent controls moving under the user’s finger.
- Landscape phones may use a 2×2 answer grid only when `min-width: 640px`; portrait phones always use one column.
- Long Vietnamese questions wrap naturally; never clip or horizontally scroll text. Room codes may wrap only at character boundaries if the viewport is exceptionally narrow.

## Accessibility contract

- Use landmarks: `header`, `main`, `section`, and `footer`; give the question stage one `h1`/heading and use `h2` for result sections.
- Every input has a visible label above it. Helper text and validation text are associated with `aria-describedby`; errors use `aria-invalid=true`.
- Answer choices are real `<button>` elements, not clickable `<div>` elements. Their accessible name includes the letter and complete answer text.
- Keyboard users can reach all actions in DOM order. Support `A`, `B`, `C`, `D` and `1`, `2`, `3`, `4` as answer shortcuts only while the player question is active; show a small helper line so this is discoverable.
- Every focusable control has a visible `:focus-visible` ring at least 2px using `#74C0FC` with 2px offset. Never remove the browser focus indicator without replacing it.
- After room join, move focus to the lobby heading. After a new question, move focus to the question heading, not directly to an answer that could be accidentally activated.
- Use `aria-live=polite` for connection, answer acknowledgement, reveal explanation, and voice transcript. Do not announce every timer second; announce `Còn 10 giây` and `Còn 5 giây` once each.
- The timer must expose text such as `Còn 18 giây` and an `aria-label`; the progress bar/ring is supplementary.
- Correct, incorrect, timeout, paused, and offline states include text and/or icons in addition to color.
- Maintain WCAG AA contrast: primary text against dominant/secondary surfaces at 4.5:1 minimum; large display text at 3:1 minimum; focus ring clearly distinct from both surface and component.
- Respect `prefers-reduced-motion`: disable confetti, shake, shimmer, leaderboard reordering animation, and automatic decorative loops; retain instant state changes and status text.
- Audio is opt-in after a user gesture. A visible transcript/announcement remains available when audio is muted, blocked, unsupported, or no Vietnamese voice exists.
- Do not use emoji in buttons, labels, announcements, or alt text. Use inline SVG icons plus Vietnamese text.

## Motion and interaction behavior

Motion is purposeful, short, and transform/opacity-only. It must communicate room state without making a 30-second question feel delayed.

| Trigger | Behavior | Duration/easing | Reduced-motion behavior |
|---------|----------|-----------------|-------------------------|
| Screen enters | Fade content in and translate Y by 8px | 180ms, `cubic-bezier(0.16, 1, 0.3, 1)` | Instant |
| Button press | Scale to `0.98` and translate Y by 1px | 100ms | Instant pressed state |
| Question/reveal change | Crossfade question region; preserve card geometry | 180ms | Instant swap |
| Correct answer | Brief confetti burst contained within question stage; success panel rises in | 700ms visual, no blocking | No confetti; show success icon/text |
| Incorrect answer | Local answer group shake | 400ms | No shake; show error border/icon/text |
| Timer warning | Numeric timer pulses once at 10s and once at 5s; progress color changes | 300ms per pulse | Color/text change only |
| Leaderboard update | Rows reorder with translate/opacity, no height animation | 240ms stagger max 40ms | Instant reorder |
| Loading | Skeleton shimmer matches content geometry | 1.2s loop | Static skeleton |

Never animate `top`, `left`, `width`, or `height`. Keep confetti pointer-events-none, clipped to the stage, and remove it after completion.

## Audio and voice behavior

| Event | Audio behavior | Visible fallback |
|-------|----------------|------------------|
| First room interaction | Offer `Bật âm thanh` after a user gesture; do not autoplay before consent | Audio control remains visible |
| Lobby ready | Optional short fixed audio phrase | `Phòng đã sẵn sàng.` |
| Quiz start | Short fixed start cue | `Ván chơi bắt đầu.` |
| Correct/incorrect reveal | Success or failure SFX, never louder than voice | Result text and score |
| Timer expired | Short time-up SFX | `Hết giờ.` |
| Fastest correct | Dynamic `SpeechSynthesis` using `vi-VN` where available | `AnnouncementRegion` always displays the sentence |
| Final result | Fixed result cue plus dynamic top-five voice, once | Top-five ranking remains visible |
| Ordinary question transition | No voice announcement | Question number and progress marker |

Audio controls:

- Background music is a light loop at approximately 0.16 volume; SFX target approximately 0.45; voice target approximately 0.8.
- Duck background music to approximately 0.05 while voice speaks, restore it on `end`/`error`/`cancel`.
- Expose one persistent mute control with text: `Tắt âm thanh` / `Bật âm thanh`. The control covers music, SFX, and voice; do not require users to find separate audio settings on a phone.
- If no Vietnamese browser voice is available, use the visible announcement and do not block the game. If fixed audio assets are unavailable, use visible text plus browser speech where supported.
- Cancel stale speech before speaking the next room announcement. Do not queue multiple fastest-player announcements.
- Any included fixed voice asset must have a license cleared before shipping. If clearance is uncertain, use browser speech plus visible text rather than shipping the model.

## Destructive actions

Only the host can perform actions that terminate shared progress.

| Action | Confirmation behavior |
|--------|-----------------------|
| `Kết thúc ván chơi` | Open a modal with focus trap and exact copy `Kết thúc ván chơi? Người chơi sẽ không thể trả lời các câu còn lại.` Primary destructive button is `Kết thúc ván chơi`; secondary is `Tiếp tục chơi`. Escape and backdrop click cancel. |
| Host `Rời phòng` while live | Use the same confirmation pattern, explaining that the room will pause for remaining players; never silently close the room. |
| Player `Rời phòng` | Confirm on the lobby/question view if a live room is active; copy `Rời phòng? Câu hỏi hiện tại sẽ không được tính cho bạn.` No deletion of saved scores is offered. |

There is no UI to delete or edit a submitted answer, score, or leaderboard result. Answer submission is intentionally irreversible for the current question.

## Implementation notes for realtime fidelity

- Render the timer from the authoritative `deadlineAt`/server clock offset; the browser timer is display-only.
- Render authoritative room events as state transitions. Do not optimistically reveal correctness, score, fastest respondent, or leaderboard order before the server response.
