<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DOM/client storage → user-visible UI | Nicknames, room codes, and server events may be untrusted text. |
| browser client → WebSocket | The client can attempt unauthorized commands or forge local timing/score state. |
| narrow/mobile device → interaction controls | Small viewport and touch/keyboard input can cause accidental or inaccessible actions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-18 | Tampering | app.js rendering | high | mitigate | Use textContent and structured state fields for nickname/room/event data; never inject untrusted HTML. |
| T-03-19 | Elevation of privilege | host controls | high | mitigate | Render controls by authoritative role and rely on DO permission checks for every command. |
| T-03-20 | Information disclosure | public client state | medium | mitigate | Keep correct answers/scores absent until authoritative reveal events; public questions omit correctOption. |
| T-03-21 | Availability | mobile controls | medium | mitigate | Enforce touch sizes, responsive no-scroll layout, focus states, and reduced-motion-safe feedback. |
</threat_model>
